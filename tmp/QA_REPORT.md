## 3. 缺陷与风险

### QA-001 高：生产水印字体不可用

API 镜像没有 `/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf`，`_font()` 回退到 Pillow 默认字体且忽略请求的字号。实测中文全部变成方框，合同、规格和时间水印整体只有约 10px，难以作为清晰证据。

证据：`tmp/qa-watermark-font.jpg`，诊断脚本 `tmp/qa_watermark_font.py`。

影响：所有新上传照片都会生成低可读性水印；当前 OSS 中只保存加水印后的文件，历史照片无法仅靠系统重新生成未加水印原图。

### QA-002 高：产品类别没有统一映射

数据库实际存在 `管道事业部`、`不锈钢盘管`、`镍基无缝管`、`焊材`、`其他`、`SMLS TUBE`、`线材其他`、`镍合金盘管` 等类别，规则文件没有对应键，约有 211 个任务会静默回退到“其它”模板。前端筛选还包含数据库中不存在的“管子/板材/棒材”，并遗漏“板棒/三角丝”。

影响：质检必拍项可能错误，业务员无法准确按产品筛选照片。

### QA-003 高：已提交任务可通过“暂存”删除必拍照片但不回退状态

完成后的任务可以进入编辑状态。删除必拍照片后点击“暂存”，数据库会删除照片，但 `mode=save` 在完成状态校验前直接返回，任务和飞书的“已提交”状态不变。

影响：页面会显示待拍，但飞书仍显示已提交，形成跨系统状态不一致。

### QA-004 高：照片是硬删除，且 OSS 没有版本控制

照片编辑删除会直接删除数据库记录和 OSS 对象；OSS 原图桶、预览桶均未配置版本控制。系统没有照片删除审计日志或软删除/tombstone。

影响：误操作无法恢复，也无法回答“何时、由谁删除了哪张证据”。`photo_status` 中已有的 `superseded` 状态尚未利用。

### QA-005 高：数据库应用账号是超级用户，API 容器以 root 运行

`qc_user` 的 `rolsuper`、`rolcreatedb`、`rolcreaterole`、`rolbypassrls` 全为 true；运行中的 API 进程 UID/GID 均为 0。

影响：API 或依赖一旦被利用，攻击者可完全控制数据库，且容器权限高于业务需要。

### QA-006 中：OSS 未配置默认加密、版本控制和生命周期

两个桶 ACL 均为 private，但版本控制为 `None`，没有默认服务端加密规则，也没有生命周期规则。

影响：误删无法恢复、静态加密和保留/清理制度缺少技术实施证据。

### QA-007 中：图片上传存在资源耗尽面

已限制单文件 15MB，但没有限制单次文件数、总解码像素或批次总处理内存。服务端会在内存中同时保存原始字节、水印图和预览图；Pillow 未设置项目级像素上限。Caddy 允许请求体最大 100MB。

影响：取得合法登录态的账号可造成高内存和 CPU 消耗；特制压缩图片可能放大解码成本。

### QA-008 中：水印处理不尊重 EXIF 方向

构造 400×200、Orientation=6 的 JPEG 后，输出仍为 400×200。正确显示应为 200×400。

影响：部分手机照片或飞书临时图片可能出现旋转方向错误。

### QA-009 中：图片库固定截断 200 条且无分页

查询固定 `LIMIT 200`，接口只返回当前数组长度，没有总数、游标或“还有更多”。当前共 278 张照片且单人尚未超过 200，因此问题尚未在现有数据中显现。

影响：数据增长后旧照片会从界面静默消失，业务员无法完整取证。

### QA-010 中：上传没有幂等键，客户端可能重复提交或误报失败

草稿 UUID 未传给后端。若服务端已提交但响应超时，客户端保留草稿并允许重试，会生成重复照片。若提交成功后的刷新请求失败，客户端还会显示“提交上传失败”，即使服务端已经保存。

影响：重复照片、误导性错误提示和人工核对成本。

### QA-011 中：任务同步只 upsert，不清理已删除的飞书任务

订单 webhook 同步当前任务集合时不会删除本地已不存在于飞书的旧任务。

影响：活动订单可能出现幽灵任务，导致首页永久有待办、整单无法完成。

### QA-012 中：缺少浏览器安全响应头

生产页面和 API 均未返回 HSTS、CSP、X-Content-Type-Options、Referrer-Policy、Permissions-Policy；API 也没有 `Cache-Control: no-store`。首页还从外部 CDN 加载无 SRI 的飞书脚本。

影响：点击劫持、脚本注入、敏感页面缓存和第三方脚本供应链风险缺少纵深防御。

### QA-013 中：前端依赖审计有高危项

`npm audit` 报告 8 个 high，其中生产依赖树 6 个 high。涉及锁定的 Vue 3.5.41、axios 1.19.0 及其部分传递依赖；Vite 高危主要影响开发服务器。当前源码未实际使用 axios，SSR 路径也未使用，因此实际可利用性低于审计数字，但仍应升级或移除未使用依赖。

### QA-014 中：健康检查不检查关键依赖

`/health` 固定返回 ok，不验证 PostgreSQL、OSS、飞书或 outbox worker。

影响：数据库或对象存储故障时监控仍可能显示健康。

### QA-015 中：生产运行配置存在漂移

运行容器环境为 `ENVIRONMENT=development`、`DEBUG=true`，与生产部署不符。初始化数据库账号同时是应用账号，且仓库没有自动备份配置，服务器外部备份需要另行确认。

### QA-016 低：媒体/筛选交互存在竞态和状态提示问题

- 搜索和筛选请求没有取消或序列号，较慢的旧请求可能覆盖新结果。
- “完成”按钮在必拍项不足时仍可点击，只弹 `alert`。
- 完成任务的补充照片备注无法单独保存；修改备注本身不算“有修改”。
- 无网络或 IndexedDB 不可用时，草稿会静默退化为内存保存，关闭页面即丢失。
- 网页相机关闭后保留禁用状态的视频轨道，部分手机可能继续显示相机占用提示。

### QA-017 低：可访问性和导航不完整

- 合同卡片只能鼠标点击，不能键盘打开。
- 导航栏显式移除了焦点轮廓。
- 相机和图片查看器没有焦点陷阱或焦点恢复。
- 页面刷新不能恢复到具体拍摄任务。
- 会话过期后的移动端跳转不携带当前返回路径。

### QA-018 低：用户停用和角色能力尚未闭环

当前共享策略已确认是“所有已登录用户共享”，不计为缺陷。但所有新用户仍自动成为 inspector；已有停用用户登录时会被 upsert 重新置为 active，且已签发的会话在过期前仍可访问照片。

## 4. 已通过的关键安全/完整性检查

- 所有业务 SQL 均使用参数占位；动态片段来自受控枚举，未发现直接 SQL 注入路径。
- Vue 模板使用文本插值，未发现 `v-html`、`innerHTML` 或 `eval` 注入路径。
- OAuth state 有签名、10 分钟时效；返回路径拒绝绝对 URL、协议相对 URL 和 `javascript:`。
- webhook 使用常量时间比较，无效密钥返回统一 401。
- Caddy 将 HTTP 301 到 HTTPS；API/PostgreSQL 未映射公网端口。
- 原图桶和预览桶 ACL 为 private；客户端只收到短期签名下载地址，不暴露 OSS 对象键。
- 数据库照片引用、拍摄人、任务关联和预览对象键当前均无孤立记录。
- 飞书状态 outbox 当前无待处理或失败项。
- 任务完成条件、自然序号排序、中文搜索词拆分、搜索通配符转义和 OAuth/Origin 校验有自动化覆盖。

## 5. 建议修复顺序

1. 修复生产水印字体和字号，并为未加水印原图建立保留策略；评估历史照片是否需要重拍或回填。
2. 建立唯一的“产品类别规范化映射”，前后端、规则引擎和存量任务共同使用。
3. 禁止对已完成任务仅“暂存删除”，或同步回退任务/飞书状态；为照片删除增加审计和软删除。
4. 增加图片分页、上传幂等键、批次文件数量和像素上限。
5. 增加 EXIF 方向处理、OSS 版本控制/加密/生命周期和可恢复备份。
6. 收紧 PostgreSQL/容器权限，修正生产环境和健康检查。
7. 补齐前端交互、可访问性、请求取消和依赖升级测试。
